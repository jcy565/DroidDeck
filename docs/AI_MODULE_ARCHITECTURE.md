# Independent engine / AI module architecture

The user wants one usable DroidDeck AI app with independently maintained engine and AI update tracks, not merely a block on upstream APK installs.

Initial implementation: a plain Java 17 Gradle library :ai-core, module version 0.1.0. It owns the AI-to-host API compatibility contract and ChatGPT exchange snapshot/ID validation. It has no Android imports, network, file I/O, native library, model runtime or dependency on :app. The application owns host API version 1, supported draft schema 1 and the trusted file tools, and depends on :ai-core one way. AiHostBridge checks the actual linked module at runtime, reports version/mismatch, and blocks new agent execution, exchange creation/acceptance, model import and share. The manual file and game tools remain independent of this gate. The contract schema describes AI exchange/draft compatibility; existing on-disk draft format is not migrated by this change.

This is the first extracted module, not complete AI isolation: GameAgent prompt/tool routing, UI and optional native inference remain in :app. The build must still contain the library. LinkageError is caught at the bridge, but process-level native crashes and actual game startup isolation need hardware tests. The AI contract does not auto-detect source incompatibility; engine changes must update the host API version when required, and CI must validate the boundary.

Update tracks:
* Engine: reviewed upstream source revision in an isolated merge branch. Run full game, API, packaging, permission, signing and regression tests before combining.
* AI code: maintain its own version and source history. Future code updates must ship in a normally signed APK (or a supported separately signed Android component, if later designed and reviewed). Do not download arbitrary dex/native code or bypass package validation. Current :ai-core is bundled; no independent over-the-air executable replacement.
* AI data/models: later add explicit signed, schema-versioned non-executable data packages with pinned trusted keys, staged validation, atomic activation, prior-version rollback, size limits and no auto-transmission. No such updater yet.
* Preserve separate AI package identity and user-managed release certificate; upstream official installer remains blocked in AI builds. Save files, AI drafts and backups must be preserved during review and migration.

Next steps: extract more portable AI planning/protocol code behind a narrow engine-owned interface; define signed AI data manifest and rollback; add version matrix and upstream merge checks; verify Android Gradle and full regression gate; trusted signing and actual device install/update; evaluate optional local runtime and ChatGPT share flow. No claim of independent APK-free AI code update or safe installation yet.

## Signed data update prototype

SignedGlossary validates a bounded DDAG binary bundle: big-endian int32 magic 0x44444147, schema 1, positive monotonically increasing revision, minimum/maximum host API, UTF-8 payload byte length, payload, signature byte length, SHA256withRSA signature over header and payload. The payload is 1–500 unique lowercase English menu phrases with tab-separated plain Korean translations, LF separators and no trailing LF; no archives, paths, executable instructions or native code. Payload max 64 KiB. Trust key is X.509 RSA 2048–4096 bits supplied by host, not embedded in the bundle. GlossaryStore re-verifies signed active/previous bytes, retains both in one host-private state file, fsyncs temp file then atomically replaces it, prevents stale imports using highest revision, supports explicit rollback if compatible, checks idle budget. Single-process only; local revision state is not a hardware anti-rollback counter, directory durability after power loss and Android filesystem behavior remain untested. Corrupt state is rejected, not silently overwritten.

App bridge uses optional build-time aiDataPublicKey (base64 X.509 public key; default empty, no trusted production key provisioned). With key configured and host compatible, the file editor can import a signed glossary and roll back. The menu provider uses validated entries over bundled defaults; unavailable/invalid data falls back to bundled dictionary; existing translations and original game files remain unchanged. No automatic download, key import from bundle, code update, model update or actual production signed bundle. Production trust key must be independently managed; no private key in repository/chat. Android compilation/device tests and publisher tooling still needed. This first data update applies only to glossary, not the neural model; large model lifecycle is separate. The core now contains explicit host-private file I/O in GlossaryStore, unlike original pure contract class.

## Independently signed model lifecycle prototype

ModelRelease adds a separate DDAM manifest (big-endian magic 0x4444414d, schema 1, positive revision, min/max host API, runtime contract API, int64 model byte length, 32-byte SHA-256, int32 signature length and SHA256withRSA signature over the 64-byte header). The existing build-pinned RSA public key authorizes the manifest; model bytes are streamed, size/hash validated, fsynced and atomically staged in an app-private directory. A bounded atomic state record retains active/previous signed manifests and highest imported revision. The active model is rehashed before inference; explicit rollback checks previous data and host/runtime compatibility. No network, arbitrary executable update, or automatic deletion. Two distinct blobs maximum; a third unique model is rejected until a future explicit retirement workflow exists. A failed state commit cleans up only its newly created blob; an interrupted process may leave an orphan; no multiprocess lock, directory fsync or hardware antirollback. ModelRuntime API 1 is a host contract for experimental MediaPipe .task, not actual model format or inference validation.

With experimentalLocalAi and the production public key configured, the app shows a two-step signed manifest / model-file import, active revision, explicit rollback and verified-active inference path. Default builds still lack local inference and a production trust key; existing manual checksum import remains experimental when the key is not configured. No actual model is supplied or tested. Actual inference, native memory/cancellation, Android Gradle/UI/installation and production key management remain unverified. Test fixtures are arbitrary bytes, not model weights. Publisher tooling and explicit model retirement are next steps. Existing official update isolation and ChatGPT manual exchange are unchanged.
