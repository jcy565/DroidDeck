# DroidDeck AI 실기기 검증 체크리스트

대상: Galaxy S23+ (8 GB RAM). 현재 검증 기록은 없음. 이 문서는 테스트 계획이며 완료 보고서가 아니다.

## 0. APK 확인 및 설치 전

- [ ] 정확한 소스 커밋과 Actions 실행 번호, APK SHA-256, 패키지 ID 및 서명 인증서 지문을 기록한다.
- [ ] 개발용 공개 테스트 키 서명 APK를 정식 배포판으로 간주하지 않는다. 실제 설치 시험은 신뢰할 수 있는 독립 서명과 정상적인 Android 설치 절차를 확인한 뒤 진행한다.
- [ ] 공식 앱과 독립판의 패키지 ID, 데이터 경로, 저장 파일 및 세이브 보호를 확인한다. 공식 앱 삭제, 데이터 초기화 또는 보안 설정 해제를 요구하지 않는다.
- [ ] 설치 실패 시 Android가 표시하는 정확한 오류를 기록하고 중단한다.

## 1. AI 및 텍스트 제작

- [ ] 복사한 테스트용 INI/CFG에서 현재 값과 제안 값이 일치하는지 확인. 취소하면 원본이 그대로인지 확인.
- [ ] 테스트용 CSV/TSV/JSON에서 원문 변수와 줄 순서 보존, 초안 저장/재개, ZIP 출력 확인. 원본과 출력본의 해시를 기록.
- [ ] ChatGPT 공유 시 미리보기와 공유된 본문이 일치하는지 확인. 민감한 데이터나 로그 전체를 공유하지 않는다.
- [ ] 다른 요청 ID, 오래된 원본, 누락된 변수 등의 응답이 적용되지 않는지 확인.
- [ ] 앱 재시작 후 저장된 요청·초안이 복원되는지 확인.
- [ ] 최신 staging 통합 이후 작업 목록 저장/복원과 오래된 원본 차단을 확인한다.

## 2. 이미지 제작

- [ ] 앱 내부 또는 사용자 소유의 복사본 PNG로 OCR → 영역 수정 → 번역 → 검토 → ZIP 내보내기.
- [ ] 일본어/중국어/라틴 문자, 회전, TGA 및 지원되는 DDS 파일을 개별 시험. 실제 지원 범위와 오류를 기록.
- [ ] 패치 불러오기, 백업, 읽기 전용 진단과 앱 내부 교체 시험이 구분되는지 확인.
- [ ] 게임 파일에 대한 실제 이미지 패치 적용/복원은 아직 UI 비활성. 실기에서 안전한 저장소와 세션 배제 조건을 검증하기 전 활성화하지 않는다.

## 3. 게임 실행 및 성능

- [ ] 같은 기기에서 공식판/검증된 독립판의 버전과 설정을 별도로 기록. 가능하면 동일 장면을 반복해 FPS와 P95 프레임타임을 측정.
- [ ] 메모리, 온도, GPU/CPU 관측값, 로그의 실패 신호를 기록. 조건이 다른 측정은 직접 비교하지 않는다.
- [ ] 실제 게임 실행 중 선택적 AI 분석과 저장소 검사 중단 여부 확인.
- [ ] 게임별 호환성 이력이 버전별로 분리되는지 확인.
- [ ] 게임 파일 수정 전에 사용자 승인 및 원본 백업이 요구되는지 확인. 위험한 자동 적용은 금지.

## 9. 독립 배포 키 생성 및 서명 준비

기존 `tools/release/make-release-key.sh`는 공식 저장소 GitHub Secrets 등록용이므로 독립판에 사용하지 않는다. 신규 `tools/release/make-ai-release-key.sh`는 본인 관리 컴퓨터의 대화형 터미널에서만 실행하며 저장소 밖의 새 비공개 디렉터리에 PKCS12 개인 키와 공개 인증서·SHA-256을 생성한다. 기존 키가 있으면 새로 생성하지 않고 기존 키와 인증서를 사용한다. 암호는 keytool 대화형 입력으로만 입력하며 저장소, 채팅, 외부 서비스에 키 또는 암호를 보내지 않는다. 생성 중 중단되면 새 키가 생겼는지 확인하고 기존 파일을 덮어쓰지 않는다.

Linux 환경에서 JDK와 신뢰할 수 있는 Android SDK build-tools(aapt, apksigner), Python 3을 준비한다. 승인된 CI APK의 SHA-256은 위 8절을 따른다. 개인 키를 안전하게 백업한 후 기존 sign-ai-apk.sh에 승인된 APK 경로, 새 출력 경로, 본인 키 경로, droiddeck-ai alias, 승인 APK 해시 및 본인이 확인한 공개 인증서 해시를 전달한다. 도구는 입력 및 출력 인증서, v2 검증, 독립 패키지 ID 및 서명 메타데이터를 제외한 payload 동일성을 확인한다. 별도 출력 APK를 재검증한 뒤에만 D01을 진행한다.

00e9742의 키 생성기를 실제 Java keytool로 일회용 테스트 디렉터리에서 시험했다. 최초 파이프 기반 시험은 keytool 재입력 문제로 실패하여 대화형 입력 전용으로 수정했다. 최종 Git blob 24fb472b52824a68abe0c5cfae0f33bfc255e4af와 동일한 파일로 대화형 생성, 공개 DER SHA-256, 개인 키 권한, 기존 경로 거부, 저장소 내부 경로 거부, 비대화형 입력 거부를 확인했다. 일회용 키는 시험 후 제거했고 실제 배포 키는 생성하지 않았다. 이 환경에는 apksigner와 aapt가 PATH에 없어 실제 APK 재서명은 미실행이다. 신규 키 생성 도구는 앱 코드와 기존 성공 CI를 변경하지 않는다.


## 10. 실제 APK의 독립 JAR(v1) 서명 검사

46111306535의 APK ZIP 및 추출 APK SHA-256을 8절의 고정값과 다시 대조했다. 로컬 OpenJDK 21.0.12.1의 jarsigner -verify -verbose -certs가 jar verified를 반환했으며 payload digest SHA-256, 서명 SHA256withRSA를 보고했다. keytool -printcert -jarfile의 인증서 SHA-256은 공개 테스트 키 a40da80a59d170caa950cf15c18c454d47a39b26989d8b640ecd745ba71bf5dc와 일치했다. 자체 서명 인증서, 신뢰 체인 미확립, 인증서 자체의 SHA1withRSA 및 JarFile/JarInputStream 해석 차이에 대한 경고도 있었으며 이를 무시하지 않는다.

Java JarFile(verify=true)으로 각 일반 ZIP 항목을 끝까지 읽고 서명 메타데이터 3개를 제외한 1,009개 payload 항목 각각의 단일 CodeSigner 및 인증서 지문을 직접 검사했다. 전부 일치했다. 별도 임시 복사본의 classes.dex 마지막 바이트를 변경한 음성 대조 시험은 SecurityException(SHA-256 digest error for classes.dex)으로 거부됐다. 임시 변경본은 삭제했고 원본은 변경하지 않았다.

이 검증은 JAR(v1) 서명 및 내용 무결성의 독립 확인일 뿐 Android APK v2/v3 서명 검증이나 개인 키로 재서명한 결과가 아니다. Android SDK apksigner/aapt는 로컬에서 찾지 못했다. 공식 Android 서명 검증 및 본인 관리 키를 사용한 재서명, D01~D08 실기 시험을 모두 남겨둔다. main과 성공 CI 소스는 변경하지 않는다.

### D01 패키지 상태 기록

승인된 본인 기기에서 독립판 설치 전과 설치 직후에 각각 `python3 tools/ai_device_packages.py`를 실행한다. 기기가 여러 대라면 `--serial`로 같은 기기를 지정한다. 두 결과를 구분해 기록하고 Android 사용자 번호가 같은지 확인한다. 숫자는 해당 패키지의 versionCode, null은 그 사용자에 대한 조회 결과에 패키지가 없음을 뜻한다. 조회 오류가 나면 결과를 보류한다.

공식판이 설치돼 있었다면 설치 후에도 같은 버전인지, 독립판이 별도 패키지로 표시되는지 확인한다. 도구는 앱을 설치·실행하거나 세이브를 읽지 않는다. D01 판정에는 기존 세이브와 원본 앱 확인도 필요하다.


## 11. 설치 전후 패키지 증거 비교 (후속 소스)

기존 46111306535 APK는 후속 기능 변경 전 소스 3f3eaab의 산출물이다. SDK 독립 검증 46113827368은 v2/v3 서명을 확인했으나 공개 테스트 인증서이며 개인 서명 및 실기는 미완료다. 후속 소스의 단위 테스트와 compileReleaseKotlin 통과를 새 APK 생성/설치로 간주하지 않는다.

같은 본인 기기와 Android 사용자에서 설치 전후의 읽기 전용 패키지 조회를 각각 before.json/after.json으로 저장한다. 승인된 APK의 versionCode는 실제 aapt 결과에서 확인한다. 오프라인 비교 예시는 `python3 tools/ai_device_packages.py --compare before.json after.json --expected-version VERSION_CODE` (VERSION_CODE는 실제 정수로 교체). 정상적인 최초 독립 설치에서 공식판 존재/버전 유지, 독립판 설치 전 부재 및 설치 후 기대 버전을 확인한다. 기존 독립판이 있으면 이 최초 설치용 비교는 통과하지 않는다; 삭제하거나 초기화하지 말고 별도 업데이트 시험을 계획한다. 기기 ID/서명/세이브는 도구가 확인하지 않으므로 결과가 통과해도 D01 전체 성공이 아니다. 실기 결과 D01~D08은 모두 미검증 유지.


## 12. 후속 소스 APK 빌드 준비

독립 검증 브랜치 `ai-independent-apk-verification-next`는 Build APK의 자동 push 허용 목록에 추가하지 않는다. 사용자 명시 승인 이후 GitHub Actions의 Build APK 수동 실행에서 정확한 브랜치를 선택한다. 기존 `rebuild_preloads` 기본 false를 유지한다. 해당 브랜치의 OCR 플래그는 true, 실험 로컬 AI는 기본 false, 독립 패키지는 com.droiddeck.launcher.ai. 실제 산출물에 대한 aapt/SDK 서명/인벤토리/전체 테스트 검증은 별도 필수다. 정식 main 서명/팩 게시/릴리스 조건 및 작성자·키 보호 검사는 그대로 유지한다. 실패한 테스트의 APK는 진단 전용이며 설치 후보가 아니다. 신규 빌드는 아직 시작하지 않았다.
